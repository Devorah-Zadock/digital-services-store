# מערכת זיהוי אובייקטים (Python בסיסי, ללא YOLO / OpenCV)

מערכת שלומדת לזהות סוגי אובייקטים מתוך תמונות בודדות שאת/ה מספק/ת,
ואז מסוגלת לקבל תמונה חדשה (גם באיכות נמוכה) ולהחזיר: אילו סוגי
אובייקטים נמצאים בה וכמה יחידות מכל סוג, כולל סימון ויזואלי על התמונה.

בנויה כולה עם **numpy, Pillow (PIL) ו-Flask** בלבד. אין שימוש ב-YOLO,
OpenCV או ספריות deep-learning כלשהן.

## איך זה עובד (בקצרה)

1. **אימון** (`train_model.py`): עבור כל תמונת אימון (שבה מופיע אובייקט
   בודד אחד), מחלצים "features" - וקטור מספרים שמתאר צבע, קצוות/צורה,
   ומבנה כללי של התמונה (`features.py`). כל התמונות מכל התיקיות
   נשמרות יחד לקובץ `model/model.npz`.

2. **זיהוי** (`detector.py`): כשמעלים תמונה חדשה (אולי עם הרבה
   אובייקטים), המערכת **לא** צריכה שהראתה לה כבר תמונות עם הרבה
   אובייקטים! במקום זה היא משתמשת בשיטת **"חלון נע" (sliding window)**:
   רצה עם "חלונות" (מלבנים) בגדלים שונים על פני כל התמונה, ולכל חלון
   שואלת "kNN" - מהי תמונת האימון הכי דומה לחלון הזה, ולפי זה מסווגת
   אותו (או קובעת שזה לא אובייקט בכלל, אם אין התאמה טובה מספיק).
   בסוף, חלונות חופפים שזיהו את אותו אובייקט ממש מאוחדים לזיהוי אחד
   (non-max suppression) - כדי לא לספור פעמיים.

3. **אתר** (`app.py` + `templates/index.html`): שרת Flask פשוט עם דף
   העלאת תמונה אחד. אחרי העלאה, מוצגת התמונה כשהאובייקטים מסומנים
   במלבנים צבעוניים עם תווית, וטבלה שמסכמת כמה מכל סוג נמצא.

## תשובה לשאלה: האם חובה להכניס גם תמונות עם הרבה אובייקטים?

**לא.** בזכות שיטת ה"חלון הנע", מספיק שכל תמונת אימון תכיל אובייקט
בודד אחד. המערכת "בונה" בעצמה את היכולת לספור כמה אובייקטים בתמונה
חדשה, כי היא בודקת המון אזורים קטנים בתוך התמונה ולא את כולה בבת אחת.

**המלצה חשובה (לא חובה, אבל משפרת מאוד את הדיוק):** מומלץ להוסיף גם
תיקייה בשם `BACKGROUND` עם כמה תמונות "ריקות" (רקע בלי אף אובייקט -
שמיים, קיר, כביש ריק וכו'). זה מלמד את המודל להבחין בין "יש כאן
משהו" לבין "זה סתם רקע", ומצמצם משמעותית זיהויי-שווא. שם התיקייה הזה
כבר מוגדר במערכת כ"לא אובייקט אמיתי" ולכן לעולם לא יוצג כתוצאה.

## מבנה התיקיות

```
object-detector/
├── config.py            <- כל ההגדרות הניתנות לשינוי (ר' למטה)
├── features.py          <- חילוץ מאפיינים מתמונה
├── train_model.py       <- סקריפט האימון
├── detector.py          <- לוגיקת הזיהוי (sliding window + kNN + NMS)
├── app.py                <- שרת האתר (Flask)
├── requirements.txt
├── templates/
│   └── index.html        <- דף העלאת התמונה והצגת התוצאה
├── model/                <- כאן נשמר המודל המאומן (model.npz) - נוצר אוטומטית
├── uploads/              <- תיקייה זמנית (לא חובה לגעת בה)
└── images/                <- *** כאן שמים את תמונות האימון ***
    ├── TREE/              <- דוגמה: תמונות של עץ בודד
    ├── CAR/               <- דוגמה: תמונות של רכב בודד
    └── BACKGROUND/        <- מומלץ: תמונות רקע ללא אובייקטים
```

## איפה משנים דברים

### 1. איפה קובעים את סוגי האובייקטים ואת נתיב תיקיית הלמידה

בקובץ **`config.py`**, המשתנה `IMAGES_DIR` (בהתחלת הקובץ) מצביע על
תיקיית `images/` שלצד הסקריפטים. אפשר לשנות אותו לכל נתיב אחר במחשב:

```python
IMAGES_DIR = os.path.join(BASE_DIR, "images")
# לדוגמה, אם רוצים תיקייה במקום אחר לגמרי:
# IMAGES_DIR = r"C:\Users\Devorah\Desktop\my_dataset"
```

**את סוגי האובייקטים את/ה קובעת פשוט על ידי יצירת תת-תיקיות** בתוך
`images/`, עם השם שתרצי (לדוגמה: `TREE`, `CAR`, `DOG`, `CHAIR`...).
שם התיקייה הוא בדיוק השם שיוצג בתוצאה. אין הגבלה על כמות הקטגוריות.

כל תת-תיקייה כזו צריכה להכיל תמונות (jpg / jpeg / png / bmp / webp)
שבכל אחת מהן מופיע **אובייקט בודד אחד** מאותו סוג. מומלץ 15-30+ תמונות
לכל קטגוריה (ככל שיותר - כך יותר מדויק), ורצוי במגוון זוויות/תאורה
כדי שהזיהוי יהיה חזק גם על תמונות באיכות נמוכה.

### 2. פרמטרים נוספים לכיוונון (גם ב-`config.py`)

| משתנה | מה הוא עושה |
|---|---|
| `WINDOW_SCALES` | אילו גדלי חלון בודקים בזמן הזיהוי (התאם לגודל האובייקטים בתמונות שלך) |
| `WINDOW_STEP_RATIO` | כמה צפוף סורקים - קטן יותר = מדויק אך איטי יותר |
| `KNN_NEIGHBORS` | כמה "שכנים" קרובים לוקחים בהצבעה לסיווג |
| `MAX_DISTANCE_THRESHOLD` | סף מעל כמה מרחק חלון נחשב "לא אובייקט" (רקע) |
| `NMS_IOU_THRESHOLD` | סף חפיפה לאיחוד זיהויים כפולים לאותו אובייקט |
| `MIN_CONFIDENCE` | סף ביטחון מינימלי להצגת זיהוי בתוצאה |
| `MAX_UPLOAD_DIMENSION` | לאיזה גודל מקסימלי מקטינים תמונה שהועלתה (משפיע על מהירות) |

אם יש יותר מדי זיהויי-שווא: הגדל/י את `MIN_CONFIDENCE` או הקטן/י את
`MAX_DISTANCE_THRESHOLD`. אם המערכת מפספסת אובייקטים אמיתיים: עשה/י
את ההפך, ו/או הוסף/י עוד תמונות אימון מגוונות יותר.

## איך מריצים (מ-PyCharm או מהטרמינל)

1. התקנת ספריות (פעם אחת, מטרמינל בתוך תיקיית `object-detector`):

   ```
   pip install -r requirements.txt
   ```

2. שמים תמונות אימון בתוך `images/<שם_קטגוריה>/` (ר' למעלה).

3. מריצים את סקריפט האימון:

   ```
   python train_model.py
   ```

   בסיום ייווצר קובץ `model/model.npz`. כל פעם שמוסיפים/משנים תמונות
   אימון צריך להריץ את זה מחדש כדי לעדכן את המודל.

4. מריצים את שרת האתר:

   ```
   python app.py
   ```

   ואז נכנסים בדפדפן לכתובת שתוצג בקונסולה (בדרך כלל
   `http://127.0.0.1:5000`), מעלים תמונה, ולוחצים "זהה אובייקטים".

## מגבלות שכדאי לדעת עליהן

- זו שיטת זיהוי קלאסית (מבוססת features + kNN), לא רשת נוירונים
  עמוקה - היא פשוטה, מהירה ללמידה, ועובדת בלי GPU, אבל **לא תגיע
  לרמת דיוק של מודלים כמו YOLO**. ככל שתהיה גיוון רב יותר בתמונות
  האימון (זוויות, תאורה, מרחקים, איכויות) - הדיוק ישתפר משמעותית.
- תמונות באיכות נמוכה מאוד (מטושטשות/פיקסליות) הן בדיוק מה שהמערכת
  מתוכננת לטפל בו (המאפיינים מבוססים על היסטוגרמות וצורה כללית, לא
  על פרטים עדינים) - אך אין החלפה לכמות ואיכות תמונות אימון טובה.
- הרצת "חלון נע" על תמונה גדולה יכולה לקחת כמה שניות (טהור Python +
  numpy, ללא האצת GPU). `MAX_UPLOAD_DIMENSION` ב-`config.py` שולט על
  זה - אפשר להקטין אותו כדי לזרז, על חשבון קצת דיוק.
