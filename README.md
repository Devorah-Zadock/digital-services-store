# BizKit — אתר מכירת תבניות עסקיות

אתר סטטי (HTML/CSS/JS בלבד, ללא בקאנד) למכירת תבניות עסקיות מוכנות — קורות חיים מותאמים אישית, מצגות עסקיות ובהמשך גם מדריכי אוטומציה חינמיים ל-Make.

## מבנה הפרויקט

```
index.html                בית
products.html              קטלוג המוצרים (מסונן לפי קטגוריה, נבנה מ-js/products-data.js)
product.html                עמוד מוצר גנרי — קורא ?slug= ומציג את הפרטים מתוך products-data.js
builder.html                 בילדר קורות חיים חי: עריכה + תצוגה מקדימה + הורדת PDF אחרי רכישה
about.html                 אודות
contact.html                צור קשר
css/style.css               עיצוב כללי של האתר (משתני צבע במעלה הקובץ)
css/builder.css              עיצוב ייעודי לעמוד הבילדר + מדיה של הדפסה
js/products-data.js           מקור האמת לכל המוצרים בקטלוג
js/catalog.js                 רינדור הקטלוג, הפילטרים ועמוד המוצר הגנרי
js/cv-content.js              תוכן ברירת מחדל + פלטת בסיס לכל תבנית קו"ח (לבילדר)
js/cv-render.js               פונקציית הרינדור של קורות החיים ל-HTML (משותפת לתצוגה ולהדפסה)
js/color-utils.js             גזירת פלטת צבעים מלאה מצבע ראשי אחד שהמשתמש בוחר
js/builder.js                  לוגיקת הבילדר: טופס חי, אימות רישוי מול Gumroad, ייצוא PDF
js/main.js                    תפריט מובייל + טופס יצירת קשר
images/previews/               תמונות תצוגה מקדימה של המוצרים בקטלוג
```

## הרצה מקומית

אין תלות בשום כלי בנייה — פותחים את `index.html` בדפדפן, או מריצים שרת סטטי פשוט:

```bash
python3 -m http.server 8000
```

## פריסה (Deploy)

אתר סטטי טהור — אפשר לפרוס בחינם ב-GitHub Pages, Netlify או Vercel, פשוט על ידי חיבור הריפו.

## איך זה עובד: קורות חיים מול מצגות

שני סוגי המוצרים באתר נמכרים בצורה שונה בכוונה:

- **קורות חיים** נערכים **בבילדר החי** (`builder.html`) — המשתמש ממלא את הפרטים שלו, בוחר צבע, ורואה תוצאה חיה. הורדת ה-**PDF** הסופי (לא Word) נפתחת רק אחרי שהוא מזין קוד רישוי תקין שקיבל מ-Gumroad. כך כל קובץ שיוצא הוא מסמך אישי וממוסה, לא תבנית גנרית שאפשר להעביר הלאה.
- **מצגות** (כרגע: תבנית פרופיל חברה) נמכרות כקובץ **PowerPoint מלא**, בדיוק כמו אצל כל חנות תבניות (Etsy, Canva וכו') — כי בשונה מקו"ח, מצגת עסקית היא מסמך שממשיכים לערוך לאורך זמן (מוסיפים שקפים, מעדכנים נתונים), ולכן אין טעם לנעול אותה מאחורי בילדר חד-פעמי.

## חשוב לפני שהאתר עולה לאוויר: חיבור Gumroad

### 1. מצגת (biz-deck-profile) — כרגע פשוט:

קובץ ה-pptx לא נמצא בריפו — הוא נשלח אליך ישירות. מעלים אותו ל-Gumroad (או Payhip/Lemon Squeezy) כמוצר רגיל עם קישור תשלום, ומחליפים את ה-`href` המסומן ב-`TODO` בתוך `js/catalog.js` (החלק שמרנדר מוצרי `deck`) בקישור האמיתי.

### 2. קורות חיים — דורש הפעלת "מפתחות רישוי" ב-Gumroad:

לכל אחת מ-7 תבניות הקו"ח, ב-Gumroad:

1. יוצרים מוצר (אפשר "מוצר דמה" בלי קובץ מצורף — הבילדר הוא שמייצר את ה-PDF, לא Gumroad).
2. בהגדרות המוצר מפעילים **"Generate a unique license key per sale"** (זה מה שמאפשר לבילדר לאמת רכישה בלי שרת משלכם).
3. מעתיקים את ה-**permalink** של המוצר (החלק שאחרי `gumroad.com/l/` בקישור המוצר).
4. פותחים את `js/builder.js` ובאובייקט `GUMROAD_CONFIG` שבראש הקובץ, לכל `slug` (למשל `cv-general-modern`) ממלאים:
   - `permalink`: ה-permalink שהעתקתם
   - `checkoutUrl`: קישור הרכישה המלא (`https://gum.co/...` או `https://<שם-החנות>.gumroad.com/l/<permalink>`)

זהו — אין צורך בשרת נוסף. הבילדר קורא ל-Gumroad License Verification API (`api.gumroad.com/v2/licenses/verify`) ישירות מהדפדפן.

### הערה חשובה על רמת ההגנה

האימות מול Gumroad מונע **שיתוף מקרי** של הקובץ (קוד רישוי אישי, לא נשלח קובץ שאפשר להעביר) — אבל זו לא הגנת DRM אמיתית: משתמש טכני שמכיר את כלי הפיתוח של הדפדפן יכול תיאורטית לעקוף את הנעילה בצד הלקוח (למשל להריץ `window.print()` ידנית). זו בדיוק אותה רמת הגנה שיש בפועל בכל אתר תבניות סטטי בלי שרת — כדי להגיע להגנה אמיתית (שרת שמאמת את הקוד ומחזיר את ה-PDF בעצמו) יידרש רכיב שרת קטן (Cloudflare Worker / Vercel Function), שאפשר להוסיף בהמשך אם זה יהפוך לבעיה אמיתית.
